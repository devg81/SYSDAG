3. AQI INTEGRATION PLAN (new attribute — research done this session,
   NOT implemented)
-------------------------------------------------------------------

3.1 Sources investigated
    - CPCB's own official repository (app.cpcbccr.com/ccr, and
      data.gov.in under the National Data Sharing and Accessibility
      Policy, NDSAP) — the authoritative government source, same
      licensing family as Census/NFHS/NNMS already used in this
      project. Hourly/daily, STATION-level.
    - A reputable third-party re-aggregation (github.com/Vonter/
      india-cpcb-aqi) republishes CPCB's own station-level data under
      ODbL (attribution required) in Parquet/CSV — a practical
      fallback if the official CCR portal's registration/bulk-download
      process is impractical within this project's timeline.
    - CPCB's own National Air Quality Index bulletins (cpcb.gov.in)
      and the NAMP (National Air Monitoring Programme) annual-mean
      station data, 2011-2023.
    - A paid/"exclusive" aggregator (dataful.in) was found but not
      pursued — this project does not need a paid data source when a
      free official one exists.

3.2 THE CENTRAL FEASIBILITY PROBLEM (why this is not a simple add)
    Every source above reports AQI at STATION or CITY level. This
    project's schema has only `demographics.state` and
    `demographics.urban_rural` (urban/rural, a binary, not a city or
    district). There is no existing field to attach a station/city AQI
    reading to without inventing one.
    A second, structural problem: CPCB's monitoring network is
    overwhelmingly sited in cities. Averaging a state's stations into
    one "state AQI" would actually produce an URBAN-BIASED figure,
    silently misrepresenting rural patients (who are the majority of
    this project's urban_rural=rural records) as experiencing city-
    level pollution. This is a real, quantifiable bias, not a
    theoretical one — rural India has very sparse CPCB monitoring
    coverage.
    A third problem: every synthetic patient currently shares ONE
    `measured_at` date (2026-09-26, confirmed in this session's audit,
    §1) via the Encounter container (D017). CPCB data spans 2015-2026;
    an exposure "window" needs an explicit, deliberate choice of which
    year/period to pull from — not an invented per-patient history.

3.3 RECOMMENDED APPROACH (feasible with the CURRENT schema, no new
    demographic field required)
    Step A — Use state-level ANNUAL MEAN AQI (not daily), for one
    explicitly chosen reference year (e.g. the most recent full year
    with complete station coverage across most states — to be
    confirmed when this is actually implemented, not guessed now).
    Annual means smooth out day-to-day noise that a single synthetic
    date cannot meaningfully represent anyway.
    Step B — Disclose the urban-monitoring bias explicitly as a
    per-record field, exactly like D017's
    `extrapolated_beyond_source_age_range` pattern: something like
    `aqi.monitoring_station_bias: "state_mean_is_urban_station_weighted"`
    rather than silently presenting a state mean as if it applied
    equally to urban and rural patients.
    Step C — Record full provenance per record: source (CPCB via
    data.gov.in or the Vonter ODbL republication), reference year,
    AQI scale/category breakpoints used (India's own CPCB scale —
    Good/Satisfactory/Moderate/Poor/Very Poor/Severe — NOT the US EPA
    scale, which uses different breakpoints and would misclassify
    values if mixed up), and an explicit
    `aqi.geographic_resolution: "state"` field so no later consumer
    assumes city-level precision that was never generated.
    Step D — Schema change: additive only (`Patient.environmental` or
    similar, new optional dataclass) — follows the same low-risk
    precedent as D012/D015/D016/D017 (additive, backward-compatible,
    does not touch any existing field).

3.4 NOT RECOMMENDED (at this time)
    - Adding a city/district field purely to support AQI. This would
      require ITS OWN new evidence source (a city-level population
      distribution within each state, which does not currently exist
      anywhere in this project) just to make AQI slightly more precise
      — a disproportionate scope increase for one secondary attribute.
    - Per-patient historical AQI "exposure history" (multiple dates,
      trends over the patient's lifetime). No source supports
      individual-level historical reconstruction, and the record has
      no mechanism for multiple dated environmental readings today.
    - Using a global/US AQI scale or a non-CPCB source — would break
      this project's own India-specific-evidence standard for no
      benefit, since CPCB's data is free, official, and sufficient.

3.5 WHAT HAS NOT BEEN DONE YET (explicitly, so nothing is overclaimed)
    - No actual AQI numbers have been downloaded or verified for any
      specific state or year.
    - No schema/code change has been made.
    - No reference year has been chosen.
    - No human sign-off has been obtained for this approach (this is a
      new environmental-data domain, a schema change, and a new
      external data source all at once — squarely the kind of thing
      CLAUDE.md §28 reserves for an explicit checkpoint, same as every
      other domain addition in this project's history, e.g. D012/D017).

3.6 IMPLEMENTATION SEQUENCE (once approved — mirrors every prior
    successful milestone in this project, not a new process)
    1. Download/verify the actual CPCB state-annual-mean AQI figures
       for the chosen reference year (real numbers, not placeholders).
    2. Add `configs/` entries with full traceability metadata (source/
       year/population/geographic_scope/definition/limitations),
       matching every existing parameter's format.
    3. Additive schema change (new dataclass + vocabulary for AQI
       category), bump SCHEMA_VERSION, record as a new Decision in
       docs/DECISIONS.md (pattern: D012, D015, D016, D017).
    4. Generation function: deterministic lookup by
       (state, reference_year) — NOT sampled/randomized, since this is
       an observed historical fact about a place and year, not a
       population distribution to draw from.
    5. Structural validation: AQI value within its scale's valid range,
       category matches the value under CPCB's own breakpoints.
    6. Pilot on 50 records (this project's established practice before
       any full-scale change) before touching the full 100,000.
    7. Full-scale re-generation only as part of the bundled dataset
       version discussed in §2.2 — not as a standalone 100K run.
